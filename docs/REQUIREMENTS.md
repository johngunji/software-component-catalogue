# Problem statement to implementation

| Problem statement                                                     | Implemented by                                                                                                                                                    |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The catalogue holds details of potentially reusable components        | `components` table; name, description, category, type, language/notation, resource URL, key words, usage counters                                                 |
| Components can be design or code                                      | `type` is `Code` or `Design`                                                                                                                                      |
| Design may use different notations (UML, ERD, structured design, ...) | Design components store a notation chosen from UML, ERD, DFD, Structured Design, Flowchart, C4, Decision Table, Wireframe, or "Other" (`backend/src/taxonomy.js`) |
| Code may be written in different languages                            | Code components store a language chosen from a list (Java, Python, C++, ...) or "Other"                                                                           |
| A cataloguer may enter components                                     | Add Component page, `POST /api/components` (cataloguer only)                                                                                                      |
| A cataloguer may delete components                                    | Delete button on the component page, `DELETE /api/components/:id`, and bulk purge                                                                                 |
| A cataloguer may associate reuse information as a set of key words    | Key words on the add / edit forms, inline editor on the component page, `PUT /api/components/:id/keywords`; stored in `keywords` + `component_keywords`           |
| A user may query availability using key words                         | Search page, `GET /api/search`: whole-word matching, ranked, "match all / any word"                                                                               |
| Maintain how many times a component has been used                     | `components.used_count`, raised by `POST /api/components/:id/use`                                                                                                 |
| Maintain how many times it came up in a query but was not used        | `components.queried_not_used_count`; per-query detail in `query_results`                                                                                          |
| Help periodically purge unused components                             | Statistics page (cataloguer): purge report using both counters and the age of the component, bulk purge; top searches and searches with no results                |
| Classify components hierarchically                                    | `categories` with `parent_id`; Categories page to add, rename, move and delete; counts include subcategories                                                      |
| A user can browse the components in each category                     | Browse page with the category tree on the left; selecting a category shows its components and those of its subcategories                                          |
| Very large number of components                                       | Server-side paging and filtering for browse and search; one grouped query for category counts                                                                     |
| Roles                                                                 | Only "user" and "cataloguer" exist                                                                                                                                |
